## 二、实物部分（S1~S2，能打开电脑看代码）

### S1 全链路通电：让电机转、让角度回来

**一句话版：**
> "S1 让装置活过来：TIM3 输出 20kHz PWM 给 TB6612 驱动电机；AS5600 经 I2C 读摆杆绝对角度；串口双向命令。两条链各自通、合起来能同时跑。"

**详细版：**
- **数字→力**：主控写比较寄存器 → PB0 输出占空比方波 → TB6612 按占空比给电机平均电流 → 电机轴出力。方向由 AIN1/AIN2，STBY 上电默认禁能。
- **角度→数**：磁铁随轴转，AS5600 测磁场方向，`deg = RAW/4096×360 − z0`；绝对角度，上电就知道摆杆在哪，转多少圈都不累计误差。
- **串口双向**：打印走轮询，命令走 USART1 中断——**中断没在 NVIC 打开时，设备照常说话，却永远听不见你**。

**踩的墙（讲这两个最有故事性）：**
- **ARR 陷阱**：CubeMX 里 TIM3 默认 Period=65535，旧固件把 ARR 写死 3599 → "40%"档实际只有 **2.2%**（1440/65536）→ 电机只"哼哼"不转。修法：按 `htim3.Init.Period` 实时算占空比 + Period 设 3599。
- **磁铁没装到位**：`|B|=0`、AGC 卡 128、STATUS 报 ML=1 → 先查磁铁距离；装到法兰中心、间隙 1~2mm 后 `|B|` 到 1000+、MAG=OK。

**代码依据：**
```c
uint32_t pulse = duty_pct * (htim3.Init.Period + 1) / 100;
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_3, pulse);
deg = (float)raw / 4096.0f * 360.0f - z0;   /* AS5600 读 0x36 */
```

### S2 2ms 硬节拍 + 角度链 + 数据记录

**一句话版：**
> "S2 把松散循环换成 2ms 硬节拍，长出三样东西：角度链（回绕修正+展开+低通+毛刺剔除）、速度估计、环形缓冲 dump。"

**详细版：**
- **2ms 硬节拍**：`g_tick_next += SAMP_US` 累加推进（不是取 now），偶尔晚一拍自动追回；时间源用 TIM2 硬件计数器（PSC=71→1MHz，软件扩 32 位），因为 `HAL_GetTick()` 只有 1ms 分辨率、量 2ms 误差 50%。实测 `dt avg=2000 max=2002 min=1998 n=251 over=0`。
- **循环量处理（原理性的坑，如实讲）**：AS5600 输出 0~4095 循环量，**不能直接在循环量上滤波/差分**——4090→10 直接相减会得到 **−4080**（真实只差 +16）。正确顺序：**回绕修正 → 展开成连续角度 → 低通（α=0.35）→ 差分 → 限幅 ±1500°/s**。
  - **实测数据（诚实说）**：未展开的数据里 49 个大尖刺（>1200°/s）有 **21 个（约 43%）落在回绕点 ±5° 内**，说明回绕确实是尖刺来源之一；但改成展开后**仍有 66 个大尖刺**、位置与回绕无关（来自编码器毛刺），**并没有"修完就干净"**，靠最后一级限幅兜底。
- **毛刺剔除**：单拍跳变 >13.2° 判毛刺丢弃（保持旧值）。开机打印里能看到这个阈值。
- **非阻塞 dump**：阻塞发送一行 135 字符 ≈12ms，500ms 窗口只跑 20 拍、丢 6 拍；改用 `HAL_UART_Transmit_IT` + 双缓冲 + 丢帧计数后 251 拍、over=0。**宁可丢日志，不能让日志拖垮控制。**

**代码依据：**
```c
if (diff > 2048) diff -= 4096;                        /* 回绕修正 */
g_unwrap += (float)diff;                              /* 先展开 */
g_th_f += LPF_ALPHA * (g_unwrap - g_th_f);            /* 再低通 α=0.35 */
dps = (g_th_f - g_th_prev_f) * (360/4096) * (1e6/dt); /* 差分 */
if (dps > DPS_MAX) dps = DPS_MAX;                     /* 限幅 ±1500 */
```

**追问应对：**

| 追问 | 答法 |
|---|---|
| 为什么 2ms？ | 倒立摆失稳时间尺度远大于 2ms；仿真 S7 扫到 30ms 都稳定，2ms 有约 15 倍裕量，还给 I2C+计算留余量 |
| 滤波顺序为什么不能反？ | ①顺序上先滤波再差分（先差分会放大噪声）；②角度是循环量，必须先展开再滤波，否则回绕点会造出 −4080 的假差值 |
| dump 会不会拖节拍？ | 不会——非阻塞 + 双缓冲 + 允许丢帧，实测 dump 期间 dt 仍 2000µs、over=0 |
| 怎么验证节拍准？ | 开机自检；且"测量工具本身也要验证"——DWT->CYCCNT 实测不前进，改 TIM2 才稳 |

## 二·五、代码结构与分层（模块化之后，照着讲）

**一句话版：**
> "代码我拆成了四层：**hal 管时间和 IO、drivers 管 AS5600、core 是纯算法、app 是 2ms 调度和状态机**；
> 而且**头文件和实现文件也分开放**——接口全在 `inc/`、实现全在 `src/`，一眼分得清"接口"和"实现"，改接口和改实现不会混在一起。
> `main.c` 里只多挂三行，工程里多配一条 Include Paths（指向 `app_angle/inc`）。
> 拆的目的就一句——**分层不是为了好看，是为了让'改一个东西'的影响范围可预测。**"

**为什么拆（先讲动机，面试官爱听这个）：**
- **一次只改一个模块，回归面小**：改滤波器不用碰串口，改串口不用碰时间源，出了问题能立刻定位到哪一层。
- **算法零硬件依赖**：`core` 里全是回绕展开、一阶低通、毛刺剔除、测速这些纯函数，**不碰 HAL、不碰寄存器**，所以能**在 PC 上单独编译跑单测**——这是在实物上跑不了的情况下还能验证逻辑的前提。
- **走读时按"数据怎么流"指，不按行号念**——面试官看的是我知不知道每段代码为什么在那儿。

**分层（从上往下，指哪讲哪）：**

| 层 | 文件 | 干什么 |
|---|---|---|
| hal | `firmware/app_angle/inc/hal/hal_time.h + src/hal/hal_time.c` | TIM2 微秒时间源（`timebase_init` / `micros`），1 格 = 1µs |
| hal | `firmware/app_angle/inc/hal/hal_io.h + src/hal/hal_io.c` | PB0 PWM 占空比、PA0/1/2 的 AIN/STBY 读写 |
| drivers | `firmware/app_angle/inc/drivers/as5600.h + src/drivers/as5600.c` | AS5600 寄存器读、`magnet_str`、`i2c_scan` |
| core（纯算法） | `firmware/app_angle/inc/core/angle_core.h + src/core/angle_core.c` | 回绕展开 / 毛刺剔除 / 一阶低通 / 测速限幅 |
| core（纯算法） | `firmware/app_angle/inc/core/recorder.h + src/core/recorder.c` | 1200 样本环形缓冲 + dump 取点 |
| core（纯算法） | `firmware/app_angle/inc/core/cmd_parse.h + src/core/cmd_parse.c` | 一行命令 → 命令码，**纯解析、不执行任何副作用** |
| app | `firmware/app_angle/inc/app/app_angle.h + src/app/app_angle.c` | 对外 `app_angle_init` / `app_angle_loop`；2ms 调度 + 命令执行 + dump 泵 + 状态行 |
| app | `firmware/app_angle/inc/app/console.h + src/app/console.c` | `log_printf` 双缓冲非阻塞 + `TxCpltCallback` + 阻塞开关 |
| 挂载 | CubeMX 生成的 `main.c` | USER CODE 三处：include 头文件、`app_angle_init()`、`while(1)` 里的 `app_angle_loop()` |

**代码走读按这个顺序指（一条链讲到底）：**
1. **时间源** → `hal/hal_time.c`：`TIM2->PSC = 71` → 1MHz，1 格 1µs；`micros()` 用软件把 16 位计数器扩成 32 位。一句话解释："为什么不用 `HAL_GetTick()`？它只有 1ms 分辨率，量 2ms 误差有 50%。"
2. **角度链** → `core/angle_core.c` 的四个纯函数，顺序不能反：**毛刺剔除**（单拍跳变 >150 计数 ≈13.2° 就丢弃）→ **回绕展开**（差值超半圈就 ±4096，再累加成连续角度）→ **一阶低通**（α=0.35）→ **测速**（差分后限幅 ±1500°/s）。
3. **命令表** → `core/cmd_parse.c`：把 `m r s z q i k d f b p w` 这串字符变成**命令码枚举**，**只解析、不执行**；执行副作用全留在 app 层——这样解析逻辑能单测，也不会"读一行命令就把电机打开了"。
4. **调度** → `app/app_angle.c`：`app_angle_loop()` 里 `g_tick_next += SAMP_US` 累加推进；命令执行、dump 泵、状态行、脉冲/慢转/轮播定时都在这一层，**全工程只有这里碰状态**。
5. **串口打印** → `app/console.c`：双缓冲 + `HAL_UART_Transmit_IT` + `TxCpltCallback` + 丢帧计数——**宁可丢日志，也不能让日志拖垮控制**。

**⚠️ 一个要主动说清的坑（面试官翻 Keil 工程就会看到）：**
> "工程根目录里还留着 `app_motor.c`，那是我 **S1 的遗留版本**；它和现在的 `app_angle.c` **不能同时编译**——两个文件里定义了**重复的串口回调符号**（`HAL_UART_RxCpltCallback` 这类 HAL 回调是全局强符号），链接时会重定义。
> 所以我是**用新版本替代它**，**不是因为旧版写得不好，而是接口冲突**：一份工程里只能存在一套串口回调。"

**金句（可背）：**
> "**分层不是为了好看，是为了让'改一个东西'的影响范围可预测。**"

## 三、仿真部分（S1~S9，重点，也是最出彩的地方）

### 为什么仿真、仿的是什么

> "我的实物做到了感知和执行（S1~S2），但**平衡闭环还没跑通**。原因是调试中发现一个真实矛盾：
> **摆杆太轻**——雪糕棍的**重力矩只有约 11.8 mN·m**，而 **JGB37-520 减速箱输出轴的静摩擦有 5 mN·m 左右，占了 40% 以上**。
> 结果就是 **摆杆松手不倒也回不了位，卡在摩擦死区里**。
> 所以我先建了一个和我实物**完全同结构**的仿真模型（只有 2 个状态：摆角 θ、角速度 ω，控制量是电机力矩），
> 把摩擦、死区、量化噪声都建进去，用仿真把控制算法验证好，再移植到实物。"

### 3.1 模型（只有 2 个状态，别讲成 4 个）

**一句话版：**
> "转轴直驱摆的方程就一条：**I·θ̈ = k_g·sinθ − 摩擦 − 电机力矩**。没有小车位置，也没有导轨。"

**详细版：**
- I = 2.13×10⁻⁴ kg·m²（均匀杆绕端部 + 尖端质点）
- k_g = (m_s·L/2 + m_t·L)·g ≈ 11.8 mN·m（重力矩幅值）
- 摩擦：黏性 + 库仑（τ_c ≈ 5 mN·m），并实现**粘滑模型**（速度≈0 且驱动力矩小于静摩擦时锁死）
- 电机力矩：τ_m = K_m·duty/100，**符号由实物实测确定**（正占空比 → θ 减小）

**⚠️ 关键提醒**：这套系统**没有小车**。如果面试官问"小车位置怎么控的"，说明模型搞混了——
正确回答是："**我的实物是电机直驱摆杆、基座固定，没有小车和导轨**，状态只有摆角和角速度两个。"

### 3.2 核心发现：摩擦死区 —— 为什么用 PID 不用纯 PD

**这是整个项目最值钱的一段，务必讲顺。**

**一句话版：**
> "我原计划用 PD 就够了。但仿真一跑，**纯 PD 收不回去**：从 10° 起步只收到 6.5° 就停住了。
> 查原因发现是**摩擦力矩压不过**——PD 在小角度下算出的力矩比静摩擦还小，杆就锁死在那儿。"

**详细版（数据都在报告里）：**
- 从 **10°** 起步：纯 PD 停在 **6.55°**、2 状态 LQR 停在 **6.51°** —— **两个都卡死**（收敛判据下 settle=∞，这两个是 6s 末尾值）
- 从 **2°** 起步（更小）：纯 PD 停在 **2.03°**
- 换成 **PID（加积分）**：从 **2°** 起步 **1.196s 收敛到 −0.514°**（这才是定点残差）；从 **10°** 起步 **0.518s 进入 ±3° 带**，之后**不收敛到定点**，而是在直立附近做 **±2° 量级极限环**（t≥3s 实测 −2.044°~+2.296°、峰峰 4.34°）——**摩擦死区的必然结果，PID 也消不掉**
- **原理**：PD 的力矩 ∝ 偏差，偏差小时力矩就小；静摩擦是"门槛"（约 5 mN·m），力矩不够就推不动 → 停在死区里。
  积分项会**一直累积**，直到出力跨过门槛，把杆推回直立。

**顺带讲 LQR**（如果被问）：
> "LQR 我也做了。对 2 个状态的对象，LQR 得到的其实就是**用加权矩阵系统性设计出来的一组 PD 增益**，结构和 PD 等价；它同样不含积分，所以仿真里一样卡在死区（6.51°）。所以我最后选的是 PID——**不是 LQR 不好，是它在这个摩擦主导的对象上缺积分这一环**。"

### 3.3 能量起摆（成功案例，可以骄傲讲）

**一句话版：**
> "实现上就是**能量控制**：算摆杆的机械能，让电机力矩和角速度同相，能量就单调增加，把杆一步步'泵'上去——**和荡秋千一个道理**。"

**详细版：**
- E = 0.5·I·ω² + k_g·(cosθ − 1)；直立 E*=0，下垂 E=−2k_g
- 对转轴力矩直驱：**dE/dt = τ_m·ω**，只要让力矩与 ω 同相就只增不减
- 捕获条件：E ≥ −0.25 J（接近直立值）且 |θ|<45°、|ω|<25 rad/s → 切换到 PID 平衡，切换后 **0.5s** 内把限幅从 25% 线性放松到 100%
- 还有"唤醒踢"：检测到停滞（|ω| 很小）超过 0.25s 就给一个 0.3s 的定向踢力，打破静摩擦死点
- **结果：从下垂位起摆，17.98s 稳定站住**（末值 −0.048°、末 1s 均值 −0.019°，约 −0.05°）
- **角度口径别讲混**：对外、画图用的是 **0°=最低点下垂、180°=最高点直立**；仿真代码内部 θ 以**直立为 0°**（S5 的 `theta0=π` 就是从下垂位出发）。两套口径别混着报，现场统一说"从下垂位起摆"最稳。

### 3.4 安全监控

**一句话版：**
> "监测和执行分离：监测模块只产生事件和故障码，状态机负责断电。故障锁存、必须人工复位，防止反复冲击。"

**详细版 + 实测数字：**
- 传感器断连（连续 20 拍无效）→ **38ms** 内急停
- 占空比持续饱和（≥95% 连续 30 拍，相当于堵转/电流异常）→ **58ms** 内断电
- 看门狗（20ms 未喂狗）→ **20ms** 超时停机
- 摆角超 35° → **降级回起摆**（不是直接停机），这就是"优雅降级"。仿真里给 60 rad/s 强冲击后 **2.016s、|θ|=40.3°** 触发降级。
- ⭐ **这里有个我查深一层才发现的真问题（很值得主动讲）**：降级后日志里一直**没有**"重新捕获"事件。
  查到根因：捕获判据我拿的是**连展角**（转两圈后会累积到 1000° 以上）去和 ±45° 比，`|θ|<45°` 永远不成立——**判据缺陷，不是算法救不回来**。
  实测：摆物理上早就回到倒立附近（−12.7°、ω≈0、E≈0）。把判据改成**折回一圈内的角度**并给捕获窗口加 10° 滞回后，**降级 0.29s 内完成重捕获**，且不再反复切换。
  一句话收尾："**不是它回不来，是我一开始把角度表示搞错了。**"（旧稿的"41.4° / 2.998s"两个数在当前代码里跑不出来，已弃用）

### 3.5 仿真指标汇总（照表背）

## 六、可能的追问清单（考前过一遍）

1. **为什么倒立摆是开环不稳定的？** 摆杆重心在转轴上方，重力矩使偏差指数放大，必须闭环。
2. **负反馈符号为什么是第一课？** 出力方向反了会变成正反馈、系统发散。我的 S3 笔记里明确写了"先用固定占空比实测'力→倒向'的符号关系再写控制律"。
3. **你的实物有几种状态？** **只有 2 个：摆角 θ 和角速度 ω**（基座固定、无小车）。
4. **AS5600 为什么不用 MPU6050？** 绝对角度、上电即用、无累计误差、直驱同轴最简；IMU 有温漂积分漂移。
5. **2ms 节拍怎么实现的？** TIM2 硬件计数器 1MHz + 累加推进 + 开机自检；HAL_GetTick 分辨率不够。
6. **为什么要积分？** 摩擦死区。纯 PD/LQR 的力矩在小角度下压不过静摩擦（5 mN·m），会停在死区内（实测仿真：10° 起步停在 6.55°、2° 起步停在 2.03°，收敛判据下 settle=∞）；积分累积跨过门槛后才能收到 1° 以内（2° 起步 1.20s 到 −0.51°）；但受摩擦限制，10° 起步也只能到 ±2° 极限环，收不到严格 0。
7. **LQR 和 PD 什么关系？** 对 2 状态对象，LQR 是用加权矩阵系统设计出的一组 PD 增益，结构等价；没有积分就消不掉死区误差。
8. **起摆为什么能成功？** 转轴力矩直驱有 dE/dt = τ_m·ω，让力矩与角速度同相，能量单调增加；接近直立就切换 PID 捕获。
9. **安全为什么锁存？** 故障自动复归会让系统反复冲击（电机/结构），锁存 + 人工复位最稳。
10. **带源码的电脑能演示什么？** 串口实时曲线（角度/速度/节拍统计）+ d 命令 dump + 代码按模块走读（hal → core → app）；仿真可直接跑 `sim_direct.py` 复现 S1~S9。
11. **⭐ 为什么不全用 PWM？** PWM 是**执行层**（手），PID/LQR 是**决策层**（大脑）。固定占空比=固定出力，摆杆直接倒。链路：AS5600 → 控制律算占空比 → PWM 输出 → 电机。
12. **⭐ 为什么不直接用 PID 以外的东西（PID vs 其它）？** 见第 6 条；对**摩擦主导的轻杆对象**，PID 的积分是必需的一环。
