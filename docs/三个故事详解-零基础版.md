# 三个故事详解（零基础版）· 直驱摆

> ⚠️ **先说一处重要更正**：我最初参考了"小车倒立摆"（小车在轨道上跑）的资料，
> 但**你的实物是电机直驱摆杆、基座固定、没有小车也没有轨道**，只有 2 个状态（摆角 θ、角速度 ω）。
> 报告和仿真已经**按实物结构整体重做**（转轴直驱摆模型）。下面讲的全是直驱摆的真实内容。

---

## 先补 3 个基础

**① 单片机在干嘛**：一块小电脑，只会"输出信号"和"接收信号"。它一秒不停地循环："读角度 → 算 → 输出给电机"，每秒 500 次 = **2ms 一次**。

**② PWM / 占空比**：电机出力大小靠"快速开关"控制，一秒开关 2 万次（20kHz）。"开的时间占一整个周期的百分比" = 占空比。100%=全力，40%=中等，2%=没劲。

**③ 定时器与 ARR**：定时器像秒表，从 0 数到一个上限（**ARR**）再归零循环。另有比较值 **CCR**："读数 < CCR 时输出开，≥ CCR 时输出关"。
**核心公式：占空比 = CCR ÷ ARR。**

## 故事 1：电机为什么只哼哼不转（ARR 坑）

**背景**：S1 想让电机 40% 占空比转。代码写死按"上限 3600"算：`pulse = 40*3600/100 = 1440`。

**现象**：电机"嗡"一声、有声音，但轴**一动不动**。打印正常、不报错。最容易误判成接线错/电机坏。

**真因**：CubeMX 里 TIM3 的 Period（ARR）默认是 **65535**，不是 3600。
- 我以为：1440 ÷ 3600 = 40%
- 实际：1440 ÷ 65536 ≈ **2.2%**

2.2% 占空比 → 平均电压很低 → 克服不了静摩擦和齿轮阻力 → 只响不转。
（好比"这节课 45 分钟讲到第 36 分钟"=80%，但这节课其实 655 分钟，讲第 36 分钟只有 5.5%。）

**修法**：① 代码改成读真实 ARR 实时算；② CubeMX 里 ARR 改 3599 → 20kHz（72MHz÷3600）。修完电机正常转。

**面试那句**："让程序把自己的配置打印出来，比拿万用表到处戳快得多——配置是软件和硬件之间唯一的约定。"

## 故事 2：速度为什么冒出尖刺（循环量坑，含更正）

> ⚠️ 我第一版把这事讲成了"我修掉一个让速度飙到 ±1500 的 bug，修完就平滑到 ±200"。
> **这句话是错的**——核对原始 CSV 后，改完之后 ±1500 尖刺依然存在。下面是核对数据后的真实版本。

**背景**：S2 要每 2ms 读角度、滤波、**算速度**。速度 = 两次角度之差 ÷ 时间差，是**算**出来的，不是测出来的。

**要理解的原理**：AS5600 输出 0~4095（对应 0~360°），**转满一圈又回 0**——像钟表表针，这叫**循环量（回绕）**。
摆杆从 359° 缓慢转到 1°（真实只转 2°）：

| 次数 | 角度 | 原始值 |
|---|---|---|
| 1 | 359° | 4090 |
| 2 | 1° | 10 |

直接相减：10 − 4090 = **−4080** → 程序以为"倒转了 4080 个单位"。
**所以循环量不能直接滤波、不能直接差分。**

**比方**：4 位机械里程表，车从 9990 开到 10010（真走了 20km），表显示 9990→0010。
你算 0010−9990 = −9980km，等于车倒着开了 1 万公里？荒谬。

**正确做法**：① **回绕修正**（差值超半圈就加减整圈）→ ② **展开**成连续角度（可到 720°、1080°…）→ ③ **低通滤波**（α=0.35）→ ④ **差分**求速度 → ⑤ **限幅** ±1500°/s。

**代码依据（我回查了固件，都是真的）**：
- `if (diff > 2048) diff -= 4096;` → 回绕修正
- `g_unwrap += diff;` 然后 `g_th_f += 0.35*(g_unwrap - g_th_f);` → 确实是"先展开、再低通"
- 开机打印里有 `jump max=... (~13.2deg)` → 13° 毛刺剔除阈值
- `#define DPS_MAX 1500.0f` → ±1500°/s 限幅

**实测数据**：未展开数据里 49 个大尖刺中 **21 个（约 43%）落在回绕点 ±5° 内**（原理成立）；改完后**仍有 66 个大尖刺**、与回绕无关（编码器毛刺）——**没有"修完就干净"**，靠限幅兜底，**没造成功能故障**。

**面试那句**："处理顺序必须是**先展开、再滤波、再差分**，循环量直接处理会在回绕点产生假的巨大差值。但说实话，改完之后还剩零星毛刺，没造成功能问题，靠限幅兜底——我不说'改完就干净了'。"

## 故事 3：⭐ 为什么用 PID 不用纯 PD（本项目最值钱的一段）

**背景**：转轴直驱摆最直观的方案就是 PD：
```
duty = kp·e + kd·ω      // e = 摆角偏差，ω = 角速度
```
（符号由实物实测确定：**正占空比 → θ 减小**，所以压住正偏差要给正占空比。）

**现象**：仿真一跑，**PD 收不回去**——
- 从 10° 起步：纯 PD 停在 **6.55°**、2 状态 LQR 停在 **6.51°**（收敛判据下 settle=∞）
- 从 2° 起步：纯 PD 停在 **2.03°**
- 换成 PID（加积分）：**2° → 1.196s 收敛到 −0.514°**（定点残差）；**10° → 0.518s 进 ±3° 带**，之后是 **±2° 量级极限环**（t≥3s：−2.044°~+2.296°、峰峰 4.34°），**收不到严格 0**

**真因：摩擦死区。** 你的实物有两个关键力矩：
- **重力矩**（把杆拉倒的力）≈ **11.8 mN·m**
- **减速箱静摩擦**（把杆粘住的力）≈ **5 mN·m**（占重力矩 40% 以上）

PD 的力矩**正比于偏差**：偏差小 → 力矩就小。当偏差只有几度时，PD 算出来的力矩（比如 2.8 mN·m）**比静摩擦门槛（5 mN·m）还小**，根本推不动杆 → 杆就**锁死在那个角度**，永远回不到 0。

**打个比方**：你想把一扇很沉的门推到完全关上，但你手上的力气随"门缝大小"变化——门缝越小你力气越小。推到还剩一条缝时，你的力气已经小于门的摩擦阻力了，门就**卡在那儿**了。
**积分项**就是"不管门缝多小，我都持续加力"，力攒到超过摩擦门槛，门就"咔"一下关上了。

**为什么 LQR 也不行**：对 2 个状态的对象，LQR 得到的其实就是**用加权矩阵系统性设计出来的一组 PD 增益**，结构和 PD 等价；它没有积分，所以一样卡在死区。
**不是 LQR 不好，是它在这个"摩擦主导"的对象上缺了积分这一环。**

**面试那句（背这一段）**：
> "我原计划 PD 就够了，但仿真发现纯 PD 从 10° 只收到 6.5° 就停住了。查原因是**摩擦死区**：
> 我的摆杆重力矩只有 11.8 mN·m，而减速箱静摩擦有 5 mN·m，占了 40% 以上；
> PD 的力矩正比于偏差，偏差小时力矩比静摩擦还小，**推不动杆**。
> 所以加了积分（PID）：积分项一直累积到出力跨过摩擦门槛——2° 起步 1.20s 收敛到 −0.51°；10° 起步 0.52s 进 ±3° 带，之后在直立附近做 ±2° 极限环，**收不到严格 0**，这就是摩擦死区的直接证据。
> LQR 我也做了——它对 2 状态对象本质上是一组系统性设计的 PD，没有积分，一样卡在 6.51°。"

## 故事 4：起摆怎么把杆"荡"起来（成功案例）

**背景**：杆本来是垂在下面的（最低点最稳），要让它荡到直立。靠**电机力矩**给杆泵能量。

**原理（一句话）**：对转轴力矩直驱的对象，**dE/dt = τ_m·ω**——只要让电机力矩和角速度**同相**，
能量就只增不减，杆会一层层被"泵"上去。**这就是荡秋千**：在合适的时候推，越荡越高。

**实现**：E = 0.5·I·ω² + k_g·(cosθ − 1)；直立 E*=0、下垂 E=−2k_g。
- 泵摆：`duty ∝ −(E* − E)·tanh(ω/ε)`（符号要让力矩与 ω 同相）
- **捕获**：能量接近直立值（E ≥ −0.25 J）且 |θ|<45°、|ω|<25 rad/s → 切换 PID 平衡，切换后 0.5s 内把限幅从 25% 线性放松到 100%
- **唤醒踢**：如果杆卡在静摩擦死点不动（|ω| 很小），给一个定向踢力打破它

**结果**：从下垂位起摆，**17.98s 稳定站住**，末值 −0.048°、末 1s 均值 −0.019°（约 −0.05°）。

**面试那句**："起摆用能量控制：转轴力矩直驱有 dE/dt = τ_m·ω，让力矩和角速度同相，能量单调增加，
像荡秋千一样把杆泵上去；到接近直立的捕获窗口就切换 PID 稳住。仿真里 17.98 秒从下垂站住，稳态残差约 −0.05°。"

| 故事 | 现象 | 真因 | 修法 | 面试那句 |

| 1. ARR 坑 | 电机只哼哼不转 | 占空比=比较值÷上限，上限 65535 被当成 3600，40% 实际 2.2% | 按真实 ARR 实时算 | "让程序打印配置，比拿万用表乱戳快" |
