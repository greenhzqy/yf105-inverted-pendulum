## 6. S6a「41.4° 触发、2.998s 自动重捕获」深查 —— 结论：**这是判据缺陷，不是参数问题**

起因：`metrics_direct.json` 里没有 S6a，且 `S6_a_theta_events.json` 只有一条
`t=2.016 LOSE_BALANCE |θ|=40.3°`，**没有 CATCH_OK**。加长窗口重算后：

| 项 | 实测 |
|---|---|
| 模式区间（12 s 窗口） | BALANCE `[0, 2.014]` → PUMP `[2.016, 12.0]`，**从未回到 BALANCE** |
| 事件 | LOSE_BALANCE ×1，**CATCH_OK ×0** |
| 摆后来到底在哪 | 末尾停在 |θ|=1067.34°（**连展角**），折算回一圈内 = **−12.66°** —— 其实已经近似倒立、速度≈0 |
| 旧数字 41.4°/2.998s | **当前代码与参数下跑不出来**（2.998 s 无任何事件） |

### 6.1 根因：捕获判据拿**连展角**和 ±45° 比

`Machine.compute` 的 PUMP 分支里：

```python
ok = (E >= self.cp.E_capture and abs(th) < self.cp.theta_cap  # th 是连展角！
      and abs(om) < self.cp.omega_cap)
if abs(th) > np.deg2rad(35.0):        # 失衡判据同样用连展角
```

强扰动（60 rad/s）把摆打进旋转后，连展角一路累积到 1000°+，于是：

| 判据分量 | 满足率（t≥2.016 s） |
|---|---|
| `E >= −0.25 J` | 100.0% |
| `\|om\| < 25 rad/s` | 97.5% |
| `\|th\| < 45°`（连展角） | **0.0%** |
| `\|wrap(th)\| < 45°`（折回一圈内） | 93.1% |
| 三条同时（连展角口径） | **0.0%** |
| 三条同时（折回口径） | 92.8% |

→ 摆**物理上已经回到倒立附近**（−12.66°、ω≈0、E≈0），却因为角度口径永远进不了捕获窗口。
`LOSE_BALANCE` 的 40.3° 也是连展角，**与对外宣称的 41.4° 口径不同**。

### 6.2 修法验证（`_s6a_hypothesis.py` / `_s6a_fix_probe.py`，未改动正式代码）

| 版本 | 首次重捕获 | 捕获后仍 LOSE | 末值 |
|---|---|---|---|
| 原版 | **永不** | — | 1067.34°（折回 −12.66°） |
| 修法 A：判据用 `wrap(th)` | **0.282 s** 后重捕获 | 25 次（35°/45° 两线太近 → 抖动） | −0.80° |
| 修法 A+B：折回角 + 滞回 42° | **0.290 s** 后重捕获 | 2 次 | −0.91° |

修法 A+B 的实质改动（供本人拍板，**尚未写入正式代码**）：

```python
# 1) 角度口径统一（捕获与失衡判据都改用折回角）
th_w = (th + np.pi) % (2 * np.pi) - np.pi
ok = (E >= self.cp.E_capture and abs(th_w) < self.cp.theta_cap
      and abs(om) < self.cp.omega_cap)
# 2) 加滞回：捕获窗口 45° -> 42°，失衡阈值保持 35°，中间 7° 过渡带不再反复切换
if abs(th_w) > np.deg2rad(35.0):
    self.mode = 'PUMP'
```
